# پنل مدیریت وب PQTunnel

**وضعیت: آزمایشی، اختیاری و خاموش به‌صورت پیش‌فرض.**

پنل در خود فرایند `pqtunneld` اجرا می‌شود و بدون سرویس مدیریتی دارای دسترسی ریشه، وضعیت شنونده، مدت اجرای daemon، تعداد همتاها و مدت اتصال هر همتا را نشان می‌دهد. مدیر احراز هویت‌شده می‌تواند اتصال یک همتای فعال را قطع کند.

## محدوده و ایمنی

- پنل پیش‌فرض فعال نیست. فقط وقتی `PQTUNNEL_ADMIN_LISTEN` تنظیم شده باشد بالا می‌آید.
- آدرس باید IP حلقهٔ محلی باشد: `127.0.0.1:9090` یا `[::1]:9090`. آدرس wildcard یا عمومی رد می‌شود.
- هنگام فعال‌سازی، `PQTUNNEL_ADMIN_TOKEN` باید دست‌کم ۳۲ بایت داشته باشد. یک توکن تصادفی با آنتروپی بالا انتخاب و در فایل محیطی فقط-برای-root نگهداری شود؛ آن را در آرگومان خط فرمان قرار ندهید.
- پنل HTTP بدون TLS است، چون فقط روی loopback گوش می‌دهد. در مرورگر از IP عددی مثل `http://127.0.0.1:9090/` استفاده کنید، نه `localhost` یا نام دامنه؛ بررسی مبدأ برای مقابله با DNS rebinding فقط IP حلقهٔ محلی را می‌پذیرد. برای دسترسی از رایانهٔ دیگر از یک تونل مدیریتی رمزگذاری‌شده مثل SSH استفاده کنید؛ هرگز پورت پنل را مستقیماً به اینترنت منتشر نکنید.
- ورود از نشست تصادفی درون‌حافظه‌ای با انقضای ۱۲ ساعت استفاده می‌کند؛ کوکی HttpOnly و SameSite=Strict است و هنگام استفاده از TLS ویژگی Secure نیز فعال می‌شود. تغییر وضعیت به بررسی Origin و توکن CSRF نیاز دارد.
- پس از ۵ توکن نامعتبر از یک IP، تلاش‌های ورود آن IP برای ۶۰ ثانیه محدود می‌شود. ورود موفق شمارنده را پاک می‌کند و داده‌های محدودسازی در حافظه می‌مانند.
- پنل تنها داده‌های عملیاتی محدود را نشان می‌دهد؛ آدرس سوکت همتاها، مقادیر CIDR، محتوای بسته‌ها، گواهی‌ها و کلیدهای خصوصی را نمایش نمی‌دهد.
- تنها عمل تغییردهندهٔ وضعیت، قطع اتصال همتای انتخاب‌شده است. پنل سرویس systemd را راه‌اندازی/متوقف نمی‌کند و هیچ مسیر، sysctl، فایروال، NAT، گواهی یا کلید را تغییر نمی‌دهد.

## تنظیمات اختیاری

این دو متغیر در محیط فرایند daemon فعال‌سازی پنل را کنترل می‌کنند:

```ini
PQTUNNEL_ADMIN_LISTEN=127.0.0.1:9090
PQTUNNEL_ADMIN_TOKEN=replace-me
```

مقدار نمونهٔ توکن عمداً معتبر نیست و باید با یک راز تصادفی حداقل ۳۲ بایتی جایگزین شود. در صورت نبودن توکن کافی، daemon از فعال‌سازی پنل خودداری می‌کند. با حذف `PQTUNNEL_ADMIN_LISTEN` پنل کاملاً خاموش می‌شود؛ قرار دادن صرفِ توکن، شنونده‌ای باز نمی‌کند.

### تنظیم پنل برای سرویس systemd

اگر از واحد systemd مخزن استفاده می‌کنید، متغیرها را در `/etc/default/pqtunneld` قرار دهید؛ این همان فایل `EnvironmentFile` واحد `pqtunneld.service` است. اگر فایل `/etc/default/pqtunneld` وجود نداشته باشد، نصاب هنگام ساخت آن این دو گزینه را به‌صورت کامنت‌شده می‌نویسد. اگر فایل موجود باشد، برای جلوگیری از تغییر تنظیمات قبلی آن را حفظ می‌کند و خطوط پنل را اضافه نمی‌کند؛ در این حالت، متغیرها را دستی به فایل اضافه کنید. برای فعال‌سازی، خط `PQTUNNEL_ADMIN_LISTEN` را از حالت کامنت خارج کنید و یک توکن تصادفی قوی در `PQTUNNEL_ADMIN_TOKEN` بگذارید. برای ساخت توکن تصادفی قوی، فرمان زیر را در ترمینال امن اجرا کنید و خروجی را به‌عنوان مقدار `PQTUNNEL_ADMIN_TOKEN` در فایل تنظیمات قرار دهید (خروجی را در مخزن یا گزارش‌ها ذخیره نکنید):

```sh
openssl rand -hex 32
```

فایل تنظیمات باید فقط برای root خواندنی باشد:

```sh
sudo chown root:root /etc/default/pqtunneld
sudo chmod 0600 /etc/default/pqtunneld
```

پس از ویرایش، راه‌اندازی مجدد سرویس لازم است تا مقادیر جدید خوانده شوند؛ این کار اتصال‌های فعال تونل را قطع می‌کند، بنابراین زمان آن را از قبل برنامه‌ریزی کنید. برای دسترسی از رایانهٔ دیگر، پورت را عمومی نکنید؛ یک تونل SSH از رایانهٔ خود باز کنید:

```sh
ssh -N -L 9090:127.0.0.1:9090 USER@SERVER
```

سپس در مرورگر همان رایانه به `http://127.0.0.1:9090/` بروید و توکن را وارد کنید. `USER@SERVER` را با حساب و میزبان SSH خود جایگزین کنید.

این پنل یک ویژگی مدیریتی اولیه در پروژهٔ آزمایشی است، نه سامانهٔ کامل مدیریت کاربران یا لاگ ممیزی. پروژه هنوز برای استفادهٔ تولیدی مورد تأیید نیست.


## پنل مدیریتی مستقل برای سروربه‌سرور

پنل قدیمی که داخل `pqtunneld` اجرا می‌شود، فقط وضعیت و قطع اتصال peer را کنترل می‌کند. برای Start/Stop/Restart و ویرایش تنظیمات، نسخهٔ مستقل `pqtunnel-manager` اضافه شده است تا با متوقف‌شدن خود تونل خاموش نشود.

### نصب اختیاری — نصب به معنی شروع سرویس نیست

از دایرکتوری ریشهٔ سورسِ بازبینی‌شده یا بستهٔ Linux استخراج‌شده اجرا کنید:

```sh
sudo bash ./scripts/install-manager.sh --source "$PWD" --role gateway
# یا روی سرور Dialer:
sudo bash ./scripts/install-manager.sh --source "$PWD" --role dialer
```

نصاب فایل اجرایی، واحد systemd و فایل `/etc/default/pqtunnel-manager` را نصب می‌کند، اما پنل را فعال یا شروع نمی‌کند و سرویس تونل، route، firewall، NAT یا forwarding را تغییر نمی‌دهد. در فایل manager یک توکن تصادفی حداقل ۳۲ بایتی بگذارید:

```sh
openssl rand -hex 32
sudoedit /etc/default/pqtunnel-manager
```

`PQTUNNEL_MANAGER_ROLE` فقط یکی از `gateway` یا `dialer` است؛ این نقش به‌ترتیب فقط `pqtunneld.service` و `pqtunnel-client.service` را هدف می‌گیرد. هیچ نام سرویس یا فرمان دلخواهی از وب‌فرم پذیرفته نمی‌شود. پس از بازبینی فایل، پنل را صریحاً فعال کنید:

```sh
sudo systemctl enable --now pqtunnel-manager
```

به‌صورت پیش‌فرض دسترسی فقط از loopback است؛ امن‌ترین روش همچنان تونل SSH است. برای دسترسی مستقیم با IP عمومی فقط حالت HTTPS با گواهی معتبر را طبق بخش بعدی تنظیم کنید. در حالت پیش‌فرض از دستگاه مدیریت، تونل SSH بسازید:

```sh
ssh -N -L 9091:127.0.0.1:9091 USER@SERVER
```

سپس در همان دستگاه به `http://127.0.0.1:9091/` بروید. پنل با توکن جداگانهٔ مدیر وارد می‌شود.

### دسترسی مستقیم عمومی فقط با HTTPS

**دسترسی عمومی با HTTP پشتیبانی نمی‌شود.** Manager برای listener غیر-loopback وجود گواهی TLS معتبر را الزامی می‌کند و با فعال‌بودن `PQTUNNEL_MANAGER_ALLOW_INSECURE_PUBLIC_HTTP` راه‌اندازی را رد می‌کند. برای مدیریت از راه دور، یک دامنهٔ DNS به IP عمومی Gateway متصل کن و گواهی معتبری برای همان دامنه تهیه کن.

نمونهٔ نصب دستی از یک بستهٔ Linux بازبینی‌شده (یا از مسیر one-line installer که صدور گواهی را خودکار انجام می‌دهد):

```sh
sudo bash ./scripts/install-manager.sh \
  --source "$PWD" \
  --role gateway \
  --public-tls \
  --public-host control.example.com \
  --tls-cert /etc/letsencrypt/live/control.example.com/fullchain.pem \
  --tls-key /etc/letsencrypt/live/control.example.com/privkey.pem \
  --panel-port 6100
```

- `control.example.com` باید به IP عمومی Gateway اشاره کند و در SAN گواهی باشد. Manager نام دامنه را با گواهی بررسی می‌کند و TLS را از نسخهٔ 1.3 پایین‌تر نمی‌آورد.
- اگر از Certbot و ACME HTTP-01 استفاده می‌کنی، TCP/80 باید برای صدور و تمدید گواهی از اینترنت به Gateway برسد. one-line installer پروژه Certbot، renewal timer و hook راه‌اندازی مجدد Manager را آماده می‌کند.
- `--panel-port` پورت HTTPS پنل است؛ مقدار پیش‌فرض 6100 است. این پورت را در فایروال ارائه‌دهنده فقط برای IPهای مدیریتی مورد اعتماد باز کن.
- برای هر نصب، مسیر تصادفی 256 بیتی در `PQTUNNEL_MANAGER_PATH_TOKEN` نگهداری می‌شود و URL نهایی با `https://` در خروجی نصب نمایش داده می‌شود. این مسیر جای توکن ورود یا TLS را نمی‌گیرد.
- توکن ورود مستقل و کوکی نشست با ویژگی‌های Secure، HttpOnly و SameSite صادر می‌شوند. توکن و URL را در گزارش عمومی، screenshot یا ticket قرار نده.

نمونهٔ شکل URL نهایی:

```text
https://control.example.com:6100/64_HEX_CHARACTERS/
```

نمونهٔ فایل تنظیمات root-only:

```ini
PQTUNNEL_MANAGER_ROLE=gateway
PQTUNNEL_MANAGER_LISTEN=0.0.0.0:6100
PQTUNNEL_MANAGER_PUBLIC_HOST=control.example.com
PQTUNNEL_MANAGER_TLS_CERT=/etc/letsencrypt/live/control.example.com/fullchain.pem
PQTUNNEL_MANAGER_TLS_KEY=/etc/letsencrypt/live/control.example.com/privkey.pem
PQTUNNEL_MANAGER_TOKEN=...random-login-token...
PQTUNNEL_MANAGER_PATH_TOKEN=...64-lowercase-hex-characters...
PQTUNNEL_MANAGER_PUBLIC_URL=https://control.example.com:6100/64_HEX_CHARACTERS
```

Manager هیچ فایروال، NAT، forwarding یا route را خودکار تغییر نمی‌دهد. اگر پورت در فایروال میزبان یا پنل ارائه‌دهنده مجاز نباشد، URL از بیرون باز نخواهد شد. برای دسترسی محلی، پنل loopback از طریق SSH port-forwarding همچنان گزینهٔ ترجیحی است.

### قابلیت‌ها و مرز عملیات

- نمایش وضعیت systemd، PID، تنظیمات غیرمحرمانه، peerهای متصل در صورت دسترسی به control socket و ۱۰۰ خط آخر لاگ سرویس.
- Start/Stop/Restart فقط برای واحد ثابتِ نقش انتخاب‌شده؛ روی Dialer، چرخهٔ عمر سرویس ممکن است helper شبکهٔ خودش را نیز اجرا کند. این کار می‌تواند تونل و مسیرهای وابسته را موقتاً قطع کند؛ پیش از استفاده روی VPS عملیاتی، دسترسی کنسول/بازیابی خارج از تونل لازم است.
- پس از Start یا Restart موفق از پنل، واحد systemd ثابت همان نقش با `systemctl enable` برای اجرای خودکار هنگام بوت فعال می‌شود. نصب یا ساخت پروفایل به‌تنهایی سرویس تونل را شروع یا enable نمی‌کند؛ این کار فقط بعد از اقدام صریح اپراتور انجام می‌شود. Stop فقط سرویس را در همین لحظه متوقف می‌کند و enable بودن هنگام بوت را لغو نمی‌کند.
- تغییر محدودِ نشانی listener، endpoint و نام TLS، CIDRها، هویت گواهی peer و allowlist پورت‌ها. فایل ابتدا اعتبارسنجی می‌شود، نسخهٔ پشتیبان با مجوز 0600 تهیه می‌شود و اگر restart تنظیمات تازه ناموفق باشد، rollback خودکار تلاش می‌شود. default route، CIDRهای هم‌پوشان، مسیر فایل‌ها، گواهی‌ها، کلیدها، توکن‌ها و تنظیمات firewall/NAT از فرم قابل تغییر نیستند.
- قطع اتصال peer از طریق control socket خصوصی Unix با مجوز 0600. اگر Dialer همچنان فعال باشد، ممکن است خودکار دوباره متصل شود؛ «قطع» به معنی ban دائمی نیست.

این سرویس مدیریتی دسترسی سطح‌بالا به systemd و فایل تنظیمات محدودشده دارد. حتی با فیلتر عملیات و توکن، آن را فقط روی loopback قرار دهید، دسترسی SSH را محافظت کنید و پیش از تغییر کانفیگ مسیر بازیابی خارج از تونل داشته باشید.

### تست سرعت واقعی از مسیر تونل

تست سرعت به `PQTUNNEL_MANAGER_SPEEDTEST_LISTEN`, `PQTUNNEL_MANAGER_SPEEDTEST_PEER` و یک `PQTUNNEL_MANAGER_SPEEDTEST_TOKEN` جداگانه با حداقل ۳۲ بایت نیاز دارد. توکن یکسان را روی هر دو سرور تنظیم کنید و مقادیر را مطابق آدرس‌های واقعی TUN جایگزین کنید. مثال‌های زیر فقط برای توپولوژی نمونهٔ مخزن هستند:

Gateway:

```ini
PQTUNNEL_MANAGER_SPEEDTEST_LISTEN=10.66.0.1:9109
PQTUNNEL_MANAGER_SPEEDTEST_PEER=10.66.0.2:9109
PQTUNNEL_MANAGER_SPEEDTEST_TOKEN=REPLACE_WITH_SHARED_RANDOM_SECRET
```

Dialer:

```ini
PQTUNNEL_MANAGER_SPEEDTEST_LISTEN=10.66.0.2:9109
PQTUNNEL_MANAGER_SPEEDTEST_PEER=10.66.0.1:9109
PQTUNNEL_MANAGER_SPEEDTEST_TOKEN=REPLACE_WITH_THE_SAME_RANDOM_SECRET
```

همچنین باید IP هر عامل در CIDR محلی همان سمت قرار گیرد، IP مقصد در prefixهای peer/remote سمت مقابل باشد و `tcp:9109` در `PQTUNNEL_ALLOWED_DST_PORTS` هر دو سمت مجاز شده باشد. مثال Gateway معمولاً به `10.66.0.1/32` در `PQTUNNEL_LOCAL_PREFIXES` و مثال Dialer به `10.66.0.1/32` در `PQTUNNEL_REMOTE_PREFIXES` نیاز دارد؛ `10.66.0.2/32` نیز باید در prefixهای متناظر Dialer/Gateway باشد. تنظیمات را با CIDRهای واقعی هر دو میزبان بازبینی کنید؛ این مقادیر را کورکورانه کپی نکنید.

عامل تست فقط روی IP خصوصیِ صریح bind می‌شود، نیاز به توکن جداگانه دارد، هم‌زمان فقط یک انتقال می‌پذیرد و حجم هر جهت را به ۱ تا ۳۲ MiB محدود می‌کند. تست، RTT میانهٔ پنج probe و throughput تقریبی TCP در هر دو جهت را اندازه می‌گیرد؛ تست اینترنت عمومی، loss/jitter کامل یا تأیید آماده‌بودن تولیدی نیست. بعد از تغییر متغیرهای manager، سرویس `pqtunnel-manager` را restart کنید تا مقادیر تازه را بخواند. خود عامل تا وقتی IP TUN حاضر شود، برای bind دوباره تلاش می‌کند.

**هشدار:** Start/Stop/Restart و تغییر تنظیمات از طریق وب‌پنل روی سرور زنده هنوز باید بعد از آزمون آزمایشگاهی و بررسی مسیر بازیابی امتحان شود. PQTunnel همچنان نسخهٔ آزمایشی است و ممیزی مستقل امنیتی/آزمون واقعی دو VPS جایگزین نشده است.
